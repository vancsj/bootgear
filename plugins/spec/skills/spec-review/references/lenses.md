# Spec-review lenses

- `request-fit`: requirements and design match the original request and acceptance criteria.
- `clarity-completeness`: the request is clear enough to settle and no required behavior, boundary, or acceptance condition is missing.
- `architecture-fit`: the design follows established architecture; if it redesigns architecture, minimal, clean, and pragmatic choices plus best practices are explicit.
- `simplicity`: a simpler clean implementation was considered and the chosen design does not add needless machinery.
- `proportionality`: the requirements do not overcomplicate the request and the design does not overcomplicate the requirements.
- `testability`: tasks and acceptance criteria make the intended behavior and important boundaries verifiable.
