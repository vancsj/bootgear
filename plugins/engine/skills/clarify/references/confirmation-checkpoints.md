# Required confirmation checkpoints

Use only for models or source-skill selection. Keep the current run, task folder, and advisor pairings.
Leave routine design choices, goal sign-off, and mutation permissions with their owning workflow. Never run `session init`.

## Models

Show user expectations and limits, then concepts, responsibilities, relations, and boundaries.
Name the uncertainty or material change. Check if a confirmation covers the exact payload and scope.
Clear, unchanged models need no new question. Recheck changed models before affected drafting.

## Source skills

Show each candidate and scope. Keep phases and orchestration within the user's scope.
Offer invocation, use without invocation, or neither. Require a user selection.
Ask again only when the skill or scope exceeds the existing confirmation.

## Return

Use the host question tool for required confirmation. Record `user-message` or `user-confirmed-ledger-entry` references.
The caller can use the public deputy recording workflow only after confirmation.
Without interaction, return `needs-confirmation` with the full payload. Stop affected drafting and source-dependent passes.
If the interaction capability is missing, return `unavailable` with its actual diagnostic.
Return confirmation or clarification to the author. Use the existing amendment contract for any user-requested run amendment.
